## 2. 状态定义与进入优先级

十字主状态是 `VISION_ROUTE_MAIN_CROSS`（枚举值 3），子状态分为：

| 子状态 | 值 | 含义 |
|--------|-----|------|
| `VISION_ROUTE_SUB_CROSS_1` | 1 | 进入十字，检测到下角点 |
| `VISION_ROUTE_SUB_CROSS_2` | 2 | 十字中部，角点上浮至 y≥75 |
| `VISION_ROUTE_SUB_CROSS_3` | 3 | 十字深处，边界起始贴边框 |

在 NORMAL 中，十字优先于圆环检查：`cross_entry_ready()` → `left_circle_entry_ready()` → `right_circle_entry_ready()`。

## 3. 完整状态转移

```
NORMAL ──(cross_entry_ready)──→ CROSS_1 ──(cross_stage2_ready)──→ CROSS_2
                                       │
                                       └──(cross_stage3_ready)──→ CROSS_3
                                                                      │
                                                    (cross_exit_ready)│
                                                                      ▼
                                                                    NORMAL
```

### 3.1 NORMAL → CROSS_1

由 `cross_entry_ready(input)` 决定，要求全部满足：

1. `route_cross_detection_enabled == true`
2. 左右下角点都找到 (`left/right_corner_found == true`)
3. 左右角点索引有效 (`>= 0`)
4. 左右角点后贴边框行数各 ≥ `route_cross_entry_corner_post_frame_wall_rows_min`（默认 5）

物理含义：图像底部检测到左右两个下角点，且角点后的边界确实"消失"在了画面边框上（连续 ≥5 行贴边），排除偶然噪点。**这是防止误触发十字的关键滤波条件。**

### 3.2 CROSS_1 → CROSS_2

由 `cross_stage2_ready(input)` 决定（第 102-115 行）：

- 任一侧角点已找到且 `corner_y >= route_cross_stage1_enter_corner_y_min`（默认 75）

物理含义：下角点在画面中"上浮"到 y≥75，说明车已驶入十字足够深。进入 CROSS_2 时，会**冻结** CROSS_1 中最后一次检测到的下角点坐标，供 CROSS_2 阶段使用。

### 3.3 CROSS_2 → CROSS_3

由 `cross_stage3_ready(input)` 决定（第 117-128 行）：

- `left_start_frame_wall_rows >= route_cross_stage2_enter_start_frame_wall_rows_min`（默认 1）
- `right_start_frame_wall_rows >= route_cross_stage2_enter_start_frame_wall_rows_min`（默认 1）

物理含义：左右原始 trace 的起始段都开始触碰人工边框（≥1 行），说明车已进入十字深处，此时视觉特征是左右边界前半段贴边框（没有真实边界），后半段才重新出现边界。

### 3.4 CROSS_3 → NORMAL

由 `cross_exit_ready(input)` 决定（第 130-140 行）：

- `start_boundary_gap_x > 0`
- `start_boundary_gap_x < route_cross_exit_start_gap_x_max`（默认 155）

物理含义：`start_boundary_gap_x = right_pts[0].x - left_pts[0].x`，即左右边界起始点的 x 间距。当间距缩小到正常车道宽度（<155px），说明十字的"开阔区域"已过，边界重新收拢，判定为驶出十字。

## 4. 从原图边界到 IPM 输入的主流程

每帧先从 trace 结果提取 `left_regular_pts/right_regular_pts`，并复制到当前工作边界 `left_pts/right_pts`。随后检测左右下角点，若某侧下角点存在，则从该下角点向上构造辅助线（aux trace/regular），再对该侧边界做"下角点截断"，并缓存截断后的基底边界 `left_cross_base_pts/right_cross_base_pts`。这些字段被写入 `route_input`，交给 `vision_route_state_machine_update()` 得到本帧 `route_snapshot`。然后按子状态执行 CROSS_1 / CROSS_2 / CROSS_3 的边界改写。全部改写完成后，才把 `left_pts/right_pts` 复制送入 IPM 映射——十字补线和截断都在原图边界工作集里完成。

## 5. CROSS_1 处理逻辑

进入 CROSS_1 后，先执行一条硬约束：若某侧下角点没找到，则该侧边界直接置空（`left_num=0` 或 `right_num=0`），避免无角点情况下继续补线。

CROSS_1 内会持续维护"最后一次检测到的左右下角点坐标"。当任意一侧下角点 `y >= 75` 时，状态机转入 CROSS_2，并冻结这组坐标供下一阶段使用。

若某侧 aux 已建立且 `*_cross_aux_regular_num > 0`，代码会在 aux trace 中寻找方向值为 5 的上角点。当前调用是 `find_nth_or_last_dir_point_on_trace(..., target_dir=5, nth_match=6, ...)`——优先取第 6 个 `dir=5`，不足则回退到最后一个 `dir=5`，一个都没有则失败。

上角点命中时，以"下角点到上角点"生成桥接线（`build_line_points_between_with_y_step(..., y_step=2)`），再把 aux regular 在上角点之前截断，最后按 **base + bridge + aux_tail** 拼接并回写。base 优先用 `left_cross_base_pts/right_cross_base_pts`。

如果上角点仍然失败（该侧没有任何 `dir=5` 命中），该侧回退到对应 `cross_base`，不做桥接，避免错误补线。

## 6. CROSS_2 处理逻辑

CROSS_2 把 CROSS_1 冻结下来的下角点当作起点，重新执行"aux → 上角点搜索"。如果某侧找到上角点，则直接用该上角点的 `x` 向下竖直延伸到巡线起始行 `maze_start_row`，作为该侧边界；如果某侧没找到上角点，则该侧边界置空。

## 7. CROSS_3 处理逻辑

CROSS_3 使用"固定锚点 + 跳变截断点"策略：

- 左锚点 `{15, 100}`，右锚点 `{145, 100}`
- 跳变阈值 `route_cross_stage3_jump_x_threshold_px = 15`
- 截断后向前推 `route_cross_stage3_cut_forward_points = 2` 个点

代码先在 regular 边界上找相邻 x 跳变超过阈值的截断点，再把锚点与截断点连线，最后拼接 **bridge + tail** 回写到 `left_pts/right_pts`。

## 8. 运行时安全兜底

每帧在状态机 update 最前面检查（第 166-170 行）：若运行时 `route_cross_detection_enabled` 被置为 false 且当前是 CROSS 主状态，立即强制切回 NORMAL，无论处于哪个子状态。

## 9. 调试时建议重点关注字段

| 分类 | 字段 |
|------|------|
| 状态 | `route_main_state`, `route_sub_state` |
| 下角点 | `cross_lower_left/right_corner_found`, `_index`, `_x`, `_y` |
| 冻结角点 | `cross_stage2_frozen_left/right_corner_found`, `_x`, `_y` |
| 贴边统计 | `cross_left/right_corner_post_frame_wall_rows`, `cross_start_boundary_gap_x` |
| 辅助线 | `cross_left/right_aux_found`, `_trace_dir` |
| 上角点 | `cross_left/right_upper_corner_found`, `_index`, `_x`, `_y` |

这些字段能快速区分是状态机判定问题还是 CROSS_1/CROSS_2/CROSS_3 补线分支导致的问题。
