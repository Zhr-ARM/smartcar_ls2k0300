```
vision_thread: vision_loop()
  └─ vision_pipeline_process_step()
       └─ vision_image_processor_process_step()
            ├─ 1) 八邻域边界追踪（左右原始轮廓点 + dir 序列）
            ├─ 2) 十字下角点检测（对 dir 序列做软模板匹配）
            ├─ 3) 边界状态计算（贴墙行数、x 间隙、直边检测、圆环入口间隙检查）
            ├─ 4) 组装 state_machine_input
            ├─ 5) vision_route_state_machine_update(input)  ← 状态转换在此发生
            ├─ 6) 按当前十字子状态修正边界（CROSS_1 / CROSS_2 / CROSS_3）

            ├─ 8) 中线生成（按 preferred_source 偏移）

line_follow_thread: line_follow_loop() [11ms 周期]
  ├─ 读取 route_main_state / route_sub_state
  ├─ select_route_profile_selection() → NORMAL/CROSS → kNormalProfile, CIRCLE → kCircleProfile
  ├─ 选用对应 Profile 计算 PID 控制输出
  └─ 下发左右轮电机目标
```

## 2. 十字下角点识别算法

### 2.1 基本原理

基于八邻域边界追踪生成的 **dir 序列**做**软模板匹配**。dir 方向约定：

```
0=上, 1=右上, 2=右, 3=右下, 4=下, 5=左下, 6=左, 7=左上
```

十字路口典型特征：左边界从向下-左方向（dir=4/5）突变为向右-下方向（dir=1/2）；右边界呈镜像。算法通过检测前平台→过渡区→后平台的模式来定位下角点。

### 2.2 软模板结构

**前平台约束：**
- 窗口大小：`cross_lower_corner_pre_window`（默认 8）
- 最少投票数：`cross_lower_corner_pre_min_votes`（默认 7）
- 有效 dir 范围：两组相邻对 — `{4,5}` 或 `{5,6}`
- 窗口内所有有效 dir 必须完全落在**同一个**相邻对内，且 max-min ≤ 1

**过渡区约束：**
- 最大长度：`cross_lower_corner_transition_max_len`（默认 4）
- 允许的 dir 范围：`{1,2,3,4,5,6}`（几乎任意非向上方向）

**后平台约束：**
- 窗口大小：`cross_lower_corner_post_window`（默认 8）
- 最少投票数：`cross_lower_corner_post_min_votes`（默认 7）
- 有效 dir 范围：两组相邻对 — `{1,2}` 或 `{2,3}`
- 窗口内所有有效 dir 必须完全落在**同一个**相邻对内，且 max-min ≤ 1

**方向下降判定：**
- 前平台平均 dir − 后平台平均 dir **必须严格大于 2.0**
- 确保方向变化显著（从向下-左转为向右-下）

### 2.3 角点精确定位

`pick_cross_lower_corner_index_near_transition()` 选择策略（优先级递减）：

1. **过渡区第一点**（如果过渡区非空）
2. **后平台中第一个 dir=2 或 3 的点**（无过渡区时）
3. **后平台中第一个 dir=1 的点**（无 dir=2/3 时）
4. **后平台起始位置**（兜底）

### 2.4 双边配对验证

- 左右两侧独立检测
- 配对条件：两侧 y 坐标差 ≤ `cross_lower_corner_pair_y_diff_max`（默认 30 像素）
- 满足条件时设置 `pair_valid` 标志

### 2.5 实现位置

- 核心函数：[vision_image_processor.cpp:1917](../code/driver/vision/vision_image_processor.cpp#L1917) `detect_cross_lower_corner_from_dirs()`
- 角点选择：[vision_image_processor.cpp:1888](../code/driver/vision/vision_image_processor.cpp#L1888) `pick_cross_lower_corner_index_near_transition()`
- 缓存更新：[vision_image_processor.cpp:2017](../code/driver/vision/vision_image_processor.cpp#L2017) `update_cross_lower_corner_detection_cache()`

## 3. 状态机设计

### 3.1 状态枚举

**主状态：**

```cpp
VISION_ROUTE_MAIN_NORMAL   = 0  // 正常巡线
VISION_ROUTE_MAIN_CIRCLE   = 1  // 圆环
VISION_ROUTE_MAIN_STRAIGHT = 2  // 直道（当前未使用）
VISION_ROUTE_MAIN_CROSS    = 3  // 十字
```

**十字子状态：**

```cpp
VISION_ROUTE_SUB_CROSS_1  // 下角点→辅助线上角点桥接
VISION_ROUTE_SUB_CROSS_2  // 冻结角点 + 固定起点引导补线
VISION_ROUTE_SUB_CROSS_3  // 锚点裁剪（退出前清理边界碎片）
```

### 3.2 状态机输入

`vision_route_state_input_t` 共 22 个字段，十字相关的关键字段：

| 字段 | 来源 | 用途 |
|------|------|------|
| `left_corner_found` / `right_corner_found` | 下角点检测 | 十字入口判定 |
| `left_corner_x/y` / `right_corner_x/y` | 下角点检测 | 十字阶段推进判定 |
| `left_corner_index` / `right_corner_index` | 下角点检测 | 角点在边界数组中的位置 |
| `left_corner_post_frame_wall_rows` | 贴墙行计数 | 十字入口条件：角点之后边界持续贴图像边框的行数 |
| `right_corner_post_frame_wall_rows` | 同上 | 同上（右侧） |
| `left_start_frame_wall_rows` | 贴墙行计数 | CROSS_2→CROSS_3 条件：起点行是否贴边框 |
| `right_start_frame_wall_rows` | 同上 | 同上（右侧） |
| `start_boundary_gap_x` | 计算 | 十字出口条件：`right[0].x - left[0].x` |
| `frame_encoder_delta` | 电机编码器 | 状态持续时间（行程估算） |

### 3.3 状态转换图

```
                    ┌──────────────────────────────────┐
                    │                                  │
                    ▼                                  │
              ┌──────────┐                             │
              │  NORMAL  │                             │
              └────┬─────┘                             │
                   │ cross_entry_ready()               │
                   │ - 双侧角点均找到                   │
                   │ - 角点后贴边框 ≥ 5 行              │
                   ▼                                   │
              ┌──────────┐                             │
              │ CROSS_1  │ 下角点→辅助线上角点桥接      │
              └────┬─────┘                             │
                   │ cross_stage2_ready()              │
                   │ - 任一侧角点 y ≥ 75               │
                   ▼                                   │
              ┌──────────┐                             │
              │ CROSS_2  │ 冻结角点 + 固定起点引导补线   │
              └────┬─────┘                             │
                   │ cross_stage3_ready()              │
                   │ - 双侧起点行贴边 ≥ 1 行            │
                   ▼                                   │
              ┌──────────┐                             │
              │ CROSS_3  │ 锚点裁剪清理                  │
              └────┬─────┘                             │
                   │ cross_exit_ready()                │
                   │ - 0 < start_gap_x < 155           │
                   │   (赛道宽度恢复)                    │
                   └───────────────────────────────────┘
```

### 3.4 各转换条件详解

#### NORMAL → CROSS_1 (`cross_entry_ready`)

```cpp
left_corner_found && right_corner_found &&
left_corner_index >= 0 && right_corner_index >= 0 &&
left_corner_post_frame_wall_rows >= min_frame_wall_rows (5) &&
right_corner_post_frame_wall_rows >= min_frame_wall_rows (5)
```

含义：双侧下角点均检测到，且角点**之后**边界沿图像边框（左 x≤1，右 x≥158）持续至少 5 个不同 y 行。表明边界在十字路口处扩散至画面边缘——这是十字路口的强特征。

在 NORMAL 状态下检查优先级：
1. 十字入口（最高优先级）
2. 左圆环入口
3. 右圆环入口

#### CROSS_1 → CROSS_2 (`cross_stage2_ready`)

```cpp
(left_corner_found && left_corner_y >= corner_y_min (75)) ||
(right_corner_found && right_corner_y >= corner_y_min (75))
```

含义：任一侧下角点 y 坐标 ≥ 75（出现在图像中足够高处），表明车已深入十字路口，需切换到更激进的边界重建策略。

**进入 CROSS_2 时，CROSS_1 期间的最后一个下角点被冻结**，此后在 CROSS_2 全程保持不变。

#### CROSS_2 → CROSS_3 (`cross_stage3_ready`)

```cpp
left_start_frame_wall_rows >= 1 &&
right_start_frame_wall_rows >= 1
```

含义：双侧边界起点行（图像底部）均触及边框。表明车位于十字路口中心，新赛道段从边框两端开始。

#### CROSS_3 → NORMAL (`cross_exit_ready`)

```cpp
start_boundary_gap_x > 0 && start_boundary_gap_x < 155
```

`start_boundary_gap_x` = `right_pts[0].x - left_pts[0].x`

含义：两侧边界起点的 x 间距恢复到正常赛道宽度范围（>0 且 <155 像素），表明十字路口已通过，车已退出。

### 3.5 安全兜底

- CROSS 状态下未匹配任何子状态 → 复位为 `CROSS_1`
- `route_cross_detection_enabled` 在 CROSS 状态中被设 false → 强制退回 NORMAL
- 任意未知主状态 → 复位为 NORMAL

### 3.6 运行时快照

```cpp
vision_route_state_snapshot_t {
    main_state;                  // 当前主状态
    sub_state;                   // 当前子状态
    preferred_source;            // line_error 偏好源 (LEFT/RIGHT/AUTO)
    encoder_since_state_enter;   // 自上次转换以来的编码器行程
    cross_loss_count;            // 十字中丢失下角点的帧数
    left_loss_count / left_gain_count;   // 左侧边界丢失/恢复
    right_loss_count / right_gain_count; // 右侧边界丢失/恢复
}
```

## 4. 十字各阶段边界处理

### 4.1 CROSS_1：下角点桥接到辅助上角点

**边界截断：**
- 某侧下角点未命中 → 该侧边界直接丢弃（`num = 0`）
- 下角点命中 → 在下角点处截断原始边界

**辅助线构建** (`build_cross_aux_boundary`)：

1. **垂直扫描**：从下角点沿同一 x 坐标向上逐行扫描（最多 `cross_aux_vertical_scan_max_rows` = 75 行），寻找白色（赛道）→黑色（背景）的过渡点
2. **八邻域追踪**：从过渡点向上追踪边界（最多 `cross_aux_trace_max_points` = 50 点，向上 `cross_aux_trace_upward_rows_max` = 30 行）
3. **按行规则化**：将原始追踪点按每行一点抽取为规则边界

**上角点检测：**
- 在辅助追踪的 dir 序列中寻找 **第 6 个 dir=5**（或不足时取最后一个 dir=5）的点作为上角点
- 函数：`find_nth_or_last_dir_point_on_trace(trace, dirs, count, 5, 6)`

**三段式拼接：**

```
基底边界（下角点前段）→ 桥接线（下角点→上角点，y 步长=2）→ 上角点之后的辅助线尾部
```

- 桥接：`build_line_points_between_with_y_step(lower_corner, upper_corner, 2)`
- 若辅助线建立但上角点未命中 → 回退到角点截断后的基底边界，不桥接

### 4.2 CROSS_2：冻结角点 + 固定起点引导补线

CROSS_2 使用进入时冻结的下角点（不再随帧刷新），重新执行辅助线构建和上角点检测。

**与 CROSS_1 的关键区别：**
- 下角点位置**冻结**不变
- **不使用原始基底边界**，改为从固定起点出发
- 上角点未命中 → 该侧整个置空（不保留任何边界）

**拼接策略（上角点命中时）：**

```
固定起点 → 直线引导 → 上角点 → 上角点之后的辅助线尾部
```

固定起点：
- 左侧：`(x=20, y=100)` — 图像左上角附近
- 右侧：`(x=140, y=100)` — 图像右上角附近

`build_line_points_between(fixed_start, upper_corner)` 绘制直线引导线。

**上角点未命中：** 该侧 `num = 0`

### 4.3 CROSS_3：锚点裁剪

CROSS_3 处理车头离开十字路口时的边界碎片清理，通过 **x 跳变检测** 定位裁剪点，并用固定锚点桥接。

**跳变检测：**
- 在规则边界上逐点检查相邻点的 x 差值
- 阈值：`route_cross_stage3_jump_x_threshold_px`（默认 15 像素）
- 找到跳变后向前推进 `route_cross_stage3_cut_forward_points`（默认 2）个点作为裁剪点

**锚点桥接：**

```
固定锚点 → 直线桥接 → 裁剪点 → 裁剪点之后的边界尾部
```

锚点配置：
- 左侧：`(x=15, y=100)`
- 右侧：`(x=145, y=100)`

函数：[vision_image_processor.cpp:1777](../code/driver/vision/vision_image_processor.cpp#L1777) `build_cross_stage3_anchor_cut_boundary()`

**边界源优先级：** 优先使用当前工作边界（含前序截断/修正），仅在为空时回退到原始规则边界。

## 5. 巡线控制层的十字消费

### 5.1 路线 Profile 选择

`select_route_profile_selection()` 在巡线线程中每周期调用：

```cpp
switch (route_main_state) {
    case VISION_ROUTE_MAIN_CIRCLE: return kCircleProfile;
    case VISION_ROUTE_MAIN_NORMAL:
    case VISION_ROUTE_MAIN_CROSS:
    default:                       return kNormalProfile;
}
```

**当前 CROSS 状态使用与 NORMAL 完全相同的 `kNormalProfile`。** 没有专用的十字 PID 参数。

### 5.2 line_error 加权配置

`apply_line_error_profile_if_needed()` 在 `vision_line_error_layer.cpp` 中按状态切换中线采样索引和权重。目前仅对 CIRCLE 状态切换到 `kCircleProfile`，**没有针对 CROSS 的自动切换**。

然而 `pid_tuning.cpp:92` 已声明 `kCrossWeightedProfile`：

```cpp
kCrossWeightedProfile = {
    3,              // 3 个加权点
    {4, 8, 12},    // 索引（比正常更近，因为十字路口可用点数更少）
    {0.5, 0.4, 0.1}
};
```

此配置已定义但**未由状态机自动激活**。

### 5.3 preferred_source 策略

CROSS 状态下 `preferred_source` 保持为 `AUTO`（等同于 NORMAL 行为），由系统按两侧边界点数自动选择使用哪侧生成中线。圆环状态则有明确的偏好源切换（如左圆环偏好右边界）。

### 5.4 日志输出

状态转换时通过 `log_route_state_transition_if_changed()` 输出：
```
主状态: CROSS_REPAIR, 子状态: CROSS_1 → CROSS_2
PID Profile: NORMAL → NORMAL
```

## 7. 已知问题与优化方向

### 7.1 已识别问题

1. **CROSS 状态下无专用 PID Profile**：当前 CROSS_1/2/3 均使用 `kNormalProfile`，与正常巡线无差别。但十字路口的视觉特征（点数少、边界不连续、近处才见线）与正常赛道差异显著，应使用独立参数。

2. **kCrossWeightedProfile 已定义但未激活**：`pid_tuning.cpp` 中定义了 `kCrossWeightedProfile`（索引 {4,8,12}，权重 {0.5,0.4,0.1}），比正常采样点更靠近车身。但 `vision_line_error_layer.cpp` 的 `apply_line_error_profile_if_needed()` 中未对 CROSS 状态做切换。

3. **CROSS_2 固定起点硬编码**：左侧 (20,100)、右侧 (140,100) 硬编码在 [vision_image_processor.cpp:5242-5245](../code/driver/vision/vision_image_processor.cpp#L5242-L5245) 和 :5335-5338，未通过配置暴露。

4. **CROSS_3 锚点已配置化但缺乏灵活性**：锚点坐标虽然是可配置的，但在 CROSS_3 整个阶段使用固定值，未根据车辆当前位置动态调整。

5. **上角点检测依赖 "第 6 个 dir=5"**：`find_nth_or_last_dir_point_on_trace` 的 `nth_match=6` 硬编码在 CROSS_1 (:5042) 和 CROSS_2 (:5221/5313) 中，这个魔数缺乏配置支持和理论依据说明。

6. **十字出口条件仅依赖 x 间距**：`cross_exit_ready()` 仅判断 `start_boundary_gap_x`，没有结合下角点消失、中线恢复等其他信号做冗余确认，可能在某些赛道布局下误触发。

7. **下角点外推仅在圆环状态启用**：`cross_lower_corner_extrapolate_enabled` 为 `false` 且仅在圆环状态激活（:4831-4837），十字状态下被跳过。

### 7.2 可考虑的优化方向

1. **激活 kCrossWeightedProfile**：在 `apply_line_error_profile_if_needed()` 中对 CROSS 主状态切换到 `kCrossWeightedProfile`，使中线采样靠近车身。

2. **为 CROSS 状态引入独立 Route Profile**：定义 `kCrossProfile`，包含独立的 `base_speed`、`line_error_prefix_ratio`、PID 参数等，允许十字路口减速通过。

3. **CROSS_2 固定起点配置化**：将左右固定起点坐标加入 `vision_runtime_config_t`。

4. **上角点检测 nth_match 参数化**：将 "第 6 个 dir=5" 的魔数提取为配置项。

5. **增强出口条件**：结合下角点持续丢失帧数（已有 `cross_loss_count`）、中线恢复直线判定等多信号综合判断退出。

6. **CROSS_1→CROSS_2 引入编码器行程保护**：当角点 y ≥ 75 长期不满足时（例如因图像噪声角点丢失），增加超时/超距兜底推进机制。
